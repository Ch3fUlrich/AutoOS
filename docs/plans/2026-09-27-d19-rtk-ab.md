# D19 — RTK on tool output: keep it off (A/B 2026-09-27)

Decision D19 of `2026-09-25-routing-v2-spec.md` allows OmniRoute RTK on tool
output only after an A/B shows savings with no lost failure line.

**Measured** (`python3 tools/probe-rtk.py --report …`, host `omniroute ctx rtk
test` against the docker gateway, default RTK config, 10 samples: git log/diff,
grep, two probe test runs, five synthetic failures buried in ~300 passing lines):

| | |
|---|---|
| tokens | 76 074 -> 14 114 (81.4 % saved) |
| samples that lost a failure line | 7 of 10 |

What was lost, by the RTK rule that dropped it:

- `generic-output:truncate` dropped the unittest `FAIL: test_… (…)` line.
- the bash suite's `✗ <name>` line and a shellcheck `SC2086` line were
  misdetected as Go test output (`test-go:collapse`) and dropped.
- `test-pytest:strip` dropped the pytest `FAILURES` header (99.4 % saved — the
  sample collapsed to 17 tokens).
- git log/diff truncation dropped commit/diff lines that mention exit codes
  (noise for this purpose, but it shows truncation is blind to content).

**Decision: RTK stays off** for agent tool output. The savings are real, but a
worker that never sees the failing test name retries blind, and that costs more
than the tokens saved. Re-run the probe after an RTK config change (filters that
keep `FAIL`/`✗`/`E `/`error:` lines) or a new OmniRoute release; enable only
when `losing=0` and saved >= 10 %.
