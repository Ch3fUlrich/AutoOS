# Routing registry — OmniRoute combos, providers, models, routes

The one home for OmniRoute routing how-to. It folds in and supersedes the
retired predecessor skill (removed 2026-10-26; its tier-order rule is kept
verbatim in [tier-order](references/tier-order.md)). Code, tests and apply
scripts reference this skill; they do not restate it.

## Files (details: [file map](references/file-map.md))

| Path | Role |
|---|---|
| `catalog/ai-registry.json` | the ONE model truth (D-2038): providers, models, clients, routes |
| `configuration/omniroute/combos.json` | GENERATED by `render omniroute` — never hand-structured |
| `configuration/omniroute/capability-overrides.json`, `context-overrides.json`, `custom-models.json` | live-gateway override inputs, applied by their appliers |
| `configuration/omniroute/live/server-combos.json` | drift snapshot read by `apply.sh --drift` |
| `configuration/omniroute/probes/` | recorded probe TSVs + leg measurements |
| `tools/sync-ide-models.py`, `tools/sync-openhands-profiles.py` | population scripts for the opencode / OpenHands surfaces |
| `tools/probe-ledger.py` | availability ledger (state: `logs/routing/availability.json`, git-ignored) |

## ADD / MODIFY (details: [add-modify](references/add-modify.md))

Path: **registry edit -> render --check -> combo-contract -> apply --dry-run ->
GO (operator/router) -> apply**. Never reorder these steps.

1. Edit `catalog/ai-registry.json` under the [tier-order rule](references/tier-order.md).
   A new route also needs `IDE_MODEL_ORDER` in `tools/registry.py` and the
   litellm managed block in `configuration/litellm/config.yaml`.
2. `python tools/registry.py render omniroute --check` — exit 0 (with `--out`
   when the render must land in `combos.json` first).
3. `python tools/combo-contract.py` — exit 0, every combo PASS.
4. Re-render/sync every surface until green: `python tools/registry.py render
   litellm|ide|openhands|models-doc --check`, `python tools/sync-ide-models.py
   --check` (or `python tools/sync-router-tiers.py --check`).
5. `python tools/registry.py check` + `validate`, `python tools/audit-router.py
   --offline`, `pytest`, `bash configuration/omniroute/apply.sh --dry-run`
   (Windows twin `configuration/omniroute/apply.ps1 -DryRun`) — exit 0,
   shellcheck/PSScriptAnalyzer clean.
6. **GO (operator/router)**, then apply: `bash configuration/omniroute/apply.sh
   --go <ref> --go-sha <sha>`. A mutating run refuses without an explicit GO
   (fleet rule D-825) — see [add-modify](references/add-modify.md#go).

## REMOVE (details: [remove](references/remove.md))

- **Combo retired**: route id out of `routes`, into `OMNIROUTE_RETIRED_IDS`
  (`tools/registry.py`) so it renders under `combos.json` `retired` and apply
  prunes the live combo; the model row stays with a dated note.
- **Leg dead**: out of `routes.<id>.legs` **and** its `unavailable_legs` gate
  together. A declared-but-gated leg stays gated; a measured-dead leg is removed.
- **Provider gone**: its legs leave every route first, then the row goes.
- Every consumer re-rendered (ADD/MODIFY step 4), reason dated in the
  `$comment` **and** the ledger. Never merge a retired id back.

## Live state is read-only (details: [live-state](references/live-state.md))

- Read live state ONLY via the read-only MCP (RT-P5-OR-MCP) or `bash
  configuration/omniroute/apply.sh --drift` (exit 0 in sync, 1 drift, 3 unreadable).
- NEVER edit `~/.omniroute`, never write through MCP/API. Live changes go
  through `apply.sh` / `apply.ps1` only.

## Tier order and windows (details: [tier-order](references/tier-order.md))

- t1 legs `>= 600000` (`T1_MIN_WINDOW` in `tools/combo-contract.py`), renders
  1M. Legacy t2/t3 (`l2-worker`, `l3-driver` bands) render `128k`; D657 layer
  twins carry their own windows. Never infer a window from the tier name.
- Order: trial -> free -> credits -> paid, paid last, **deepseek LAST**, no free
  after paid; `-free-only` twins take no credit/paid leg.
- openrouter: every servable leg ends `:free`; declared paid legs are gated in
  `unavailable_legs` and the provider stays `available`.
- Every leg add/remove is reasoned and dated: `$comment` + `python
  tools/probe-ledger.py record --leg <provider/model> --status
  <served|failed|limited> --reason <text>`.

## Gate (fail-closed, details: [tier-order](references/tier-order.md#gate-fail-closed))

`python tools/combo-contract.py` is wired fail-closed into `configuration/
omniroute/apply.ps1` + `apply.sh` (also under the dry run: `-DryRun` on
apply.ps1, `--dry-run` on apply.sh), CI, the test harnesses and pytest. Green
gate, then GO, then apply — never apply first.
